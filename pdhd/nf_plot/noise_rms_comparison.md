# PDHD electronics noise: data vs. simulation

Per-channel electronics-noise RMS for ProtoDUNE Horizontal Drift, comparing real data against the noise-only simulation. Generated by `noise_rms_compare.py`.

## Question

Is the PDHD electronics-noise simulation consistent with data?

## Inputs and method

- **Data**: PDHD `run027409`, event 0 — raw pre-NF ADC frames (`protodunehd-orig-frames-anode{0-3}.tar.bz2`), all 4 APAs.
- **Simulation**: noise-only run of the production noise chain (`pdhd_sim/wct-sim-noise-only.jsonnet`): `EmpiricalNoiseModel` + `AddNoise` + `Digitizer`, configuration taken verbatim from `cfg/pgrapher/experiment/pdhd/sim.jsonnet`. FE gain 14 mV/fC — the run027409 gain, per `input_data/META.json` — selecting the `protodunehd-noise-spectra-14mVfC-v1.json.bz2` spectra file.
- **Noise RMS**: per channel, the WireCell sigproc `Derivations::CalcRMS` 4.5σ clip (`sigproc/src/Derivations.cxx`), iterated to convergence so signal samples are excluded, then the population RMS of the rest. Measured on the raw ADC waveform, before noise filtering.

## Result — the simulation UNDER-predicts the data noise

| 0 | U | 19.82 | 13.60 | 0.69 | 1.694 | 1.162 |
| 0 | V | 20.24 | 13.70 | 0.68 | 1.730 | 1.171 |
| 0 | W | 15.32 | 10.70 | 0.70 | 1.309 | 0.914 |
| 1 | U | 16.37 | 13.56 | 0.83 | 1.399 | 1.159 |
| 1 | V | 16.49 | 13.70 | 0.83 | 1.409 | 1.171 |
| 1 | W | 12.75 | 10.68 | 0.84 | 1.090 | 0.913 |
| 2 | U | 20.10 | 13.56 | 0.67 | 1.717 | 1.158 |
| 2 | V | 20.90 | 13.71 | 0.66 | 1.785 | 1.171 |
| 2 | W | 15.50 | 10.70 | 0.69 | 1.325 | 0.914 |
| 3 | U | 16.42 | 13.57 | 0.83 | 1.403 | 1.159 |
| 3 | V | 16.76 | 13.70 | 0.82 | 1.432 | 1.171 |
| 3 | W | 12.90 | 10.73 | 0.83 | 1.102 | 0.917 |

Three observations:

1. **The simulation under-predicts the data on every APA and plane**, with sim/data ≈ 0.66–0.84. The simulated noise is too low.
2. **The simulation is APA-uniform; the data is not.** The sim produces essentially the same RMS on all four APAs (≈13.6 / 13.7 / 10.7 ADC for U / V / W) because one spectra file and a uniform ADC config feed every APA. The data instead splits cleanly by **even/odd APA** — APA0 and APA2 (U/V ≈ 20 ADC) vs APA1 and APA3 (U/V ≈ 16.5 ADC). Even and odd APAs sit on opposite drift sides (`sign = 2*(n%2)-1` in `params.jsonnet`), so this is a **drift-side noise asymmetry** — and, driven by a single APA-uniform spectra file, one the simulation is structurally unable to reproduce.
3. **The plane ordering is qualitatively right.** W (collection) is quieter than U/V in both data and simulation.

### Contributing factor: no coherent noise in the simulation

The PDHD sim adds noise with `AddNoise` (`IncoherentAddNoise`) only — there is no `CoherentAddNoise` and no `GroupNoiseModel` in `sim.jsonnet`. Real data noise is incoherent + coherent. The missing coherent component makes the simulation lower than data, consistent with the across-the-board under-prediction seen here; the incoherent spectra file itself also appears somewhat under-tuned.

## Caveats

- **Residual signal in data**: event 0 is a real triggered event with higher channel occupancy than the PDVD event used in the sister study. A single 4.5σ clip pass over-reads the busier APAs by up to ~25%, so the clip is iterated to convergence; the converged result agrees with an independent percentile-based RMS to within a few percent.
- **APA0 V-plane**: a known APA0 V-plane anomaly affects signal/decon behaviour elsewhere; it does not show up in the raw noise RMS here — APA0 V sits with APA2 V, both in the noisier pair.
- **Tick period**: data is 512 ns/tick (native, pre-resampler), sim is 500 ns/tick. This is a sub-1% effect on ADC-count RMS and is not corrected.
- The simulation was run with `nticks = 6000`; data frames have 5859 ticks — ample statistics for a per-channel RMS in both cases.

## Conclusion

The PDHD electronics-noise simulation does **not** reproduce the data. It under-predicts the per-channel noise RMS by roughly 20-35%, and -- because it drives every APA from a single noise-spectra file — it cannot reproduce the real drift-side noise asymmetry (even APAs 0/2 noisier than odd APAs 1/3). Re-tuning the incoherent noise spectra (`protodunehd-noise-spectra-14mVfC-v1.json.bz2`) and adding a coherent noise component would be needed to match data. See `pdhd_noise_simulation.md` for how the noise model is built.
