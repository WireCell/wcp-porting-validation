Running the PR chain in our 1-step workflow

A component-level map of Xin's pattern-recognition (PR) chain, what our 1-step wcls-img-clus-matching-xin job already runs, and exactly what is missing to close the gap.

Reference: sbnd_xin/docs/pr/41_pr-chain-overview.md · toolkit ap-yuhw @ 06a02ccb · install /exp/sbnd/app/users/yuhw/opt (libs dated 2026-08-06) · written 2026-08-17

The headline. Our 1-step job already instantiates the PR node — the same MultiAlgBlobClustering instance (clus_pr) that Xin's 2-step chain runs — and already executes 8 of its 15 production stages. Turning on the full chain (neutrino tagger, both BDT scorers, the ROOT writers) is a 5-name edit to one list in wcls-img-clus-matching-xin.jsonnet. Every C++ component it needs is compiled into our installed libWireCellClus.so / libWireCellRoot.so. Three environment-level things are genuinely missing, and they are listed in §7.

1. The two chains

Xin's chain is split at the Q/L matching boundary and hands off through files. Ours is one lar process that keeps the whole thing in memory.

Truth labeling none in-chain wclsTensorSetLabeler (needs the art event → 1-step only)

The 1-step's structural advantage is that the labeler and the PR taggers see the same in-memory tree, so truth labels and tagger verdicts are attached to the identical clustering. Its structural cost is that per-event jsonnet TLAs are unavailable — the config is compiled once per lar process — which is where the RSE problem in §7 comes from.

7. Two routes, and a proposed order

Route A — extend the 1-step in place

Add the 5 (or 7, with protect_bundle+steiner_refresh) names to pipeline_names in wcls-img-clus-matching-xin.jsonnet:

pipeline_names=[
  'switch_scope','unmerge_bundle','unmerge_assoc',
  'steiner','fiducialutils',
  'tagger_check_tgm','tagger_check_stm','tagger_check_fc',
  'protect_bundle','steiner_refresh',
  'tagger_check_neutrino',
  'numu_bdt_scorer','nue_bdt_scorer',
  'tracking_visitor','tagger_output',
]

Pros: one edit; labeler truth and PR verdicts on the identical tree; no extra I/O; harness unchanged apart from keeping new outputs.
Cons: hits G1, G2, G3, G4 immediately; no per-event TLA knobs, so all ~60 SBND_* switches become compile-time choices in our entry config.

Route B — write a pctree, run the 2-step PR job on it

Set tensor_outname on clus_all_apa (G6), then run the canonical toolkit cfg/pgrapher/experiment/sbnd/wct-pr-perevt.jsonnet per event — the same file Xin's driver runs.

Pros: bit-comparable with Xin's chain by construction; per-event TLAs work, so real run/subrun/event reach Trun (G3 dissolves); nusel_extract.py and pr_scores_table.py work unmodified.
Cons: a second process and a ~pctree-sized file per event; the truth labels and the PR verdicts live in different files.

Recommendation. Do B first as the reference, then A and check A against B. B is nearly free (one jsonnet argument plus a second wire-cell call, and its jsonnet is already in our tree), it side-steps G3 and G4 entirely, and it gives us the ground truth to validate A against. Then A is what we actually run at scale, once it reproduces B. This is the same 1-step ≡ 2-step equivalence argument that already worked for the clustering+matching half.

Suggested sequence

  1. Unblock G1 — copy XGB_nue_seed2_0923.xml into our wire-cell-data. Cheap, and without it nue_score is meaningless.
  2. Decide G2 — I suggest setting dl_weights='' explicitly for now, so the geometric vertex is a recorded choice rather than a silent per-event fallback. Installing torch+sparseconvnet+SCN is a separate, self-contained task if we want the DL vertex.
  3. G6 — one-line tensor_outname, giving us a pctree.
  4. Route B pilot, 10 events — wct-pr-perevt.jsonnet with the full 15-name pipeline. Measures G7. Produces tracking-pr.root + mabc-pr.zip + nusel-evt*.tsv with correct RSE.
  5. Route A pilot, same 10 events — compare T_tagger leaf-by-leaf and the mabc-pr.zip layers against step 4. Any difference is a real 1-step/2-step divergence, not noise.
  6. Fix G4 — add bee_sink to clus_pr so PR Bee layers share mabc.zip and the event index stays aligned.
  7. Fix G3 properly — rse_from_ident in the two ROOT visitors, so Route A's ROOT output is self-identifying.
  8. Scale, once 4≡5 and the per-event cost is known.

Open questions for you

  • DL vertex: live with the geometric vertex, or invest in the torch/SCN install? Note the SCN net is uBooNE-trained either way.
  • BDT scores: both weight sets are uBooNE-trained and unretrained on SBND — usable for availability and relative ranking, not as calibrated probabilities. Is that the intended use here, or is SBND retraining part of the plan?
  • protect_bundle: include it (SBND production default since 2026-08-02) or start from the pre-pr/23 8-stage chain to keep the comparison against our existing 13k-event run clean?
  • Scope: is the target a pilot for development, or a production-scale rerun of the 13,217-event MC sample with scores attached?
