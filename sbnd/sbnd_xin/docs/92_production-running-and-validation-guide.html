SBND Wire-Cell reconstruction: production running condition and validation checklist

For colleagues integrating the Wire-Cell Toolkit (WCT) chain into LArSoft. What the production condition is, how minimal and debug outputs differ, how the multi-step and multi-event running works, what reference results exist, and a checklist to prove your integration reproduces them.

0. Read this first

The production operating point is the jsonnet file's own defaults. Since doc 68, the SBND operating point lives in exactly one place: the top-level-argument (TLA) defaults of cfg/pgrapher/experiment/sbnd/wct-pr-perevt.jsonnet (pattern recognition) and wct-clus-matching-perevt.jsonnet (clustering + Q/L matching). A bare invocation is production. The runner scripts pass only what is per-event (input, output, run/subrun/event, reality), the 15-stage PR pipeline list, and the output-file names. Anything your LArSoft job passes beyond that is a deviation. The compiled reference is committed: ref/prod-2026-09-01c/prod_prjob.json.

Five non-negotiables. Each one has cost a week somewhere in this project.

  1. Compile and diff, do not read. A jsonnet comment claiming parity is not parity. The colleague-side 1-step job (sbnd/docs/5-pr-chain-in-1step.html §11) carried the comment "match the SBND production operating point" and differed from production by 160 PR knobs, because it called clus_maker.pr() directly and inherited the conservative C++ defaults. Only a compiled-config diff to zero caught it. Checklist tier T0.
  2. reality=data must match the input's lineage. The PR job re-applies the pos_offset transverse correction gated on reality. Running a data pctree as sim (or the reverse) flips scope, in-window and PID decisions wholesale (doc pr/38 r3). Every production sample here is data.
  3. Validation arms run with the debug outputs ON. An arm produced with the Bee zip and the pctree suppressed cannot be A/B gated, and the archive gate reports it as a vacuous PASS (doc 87 §5.3, §6.4). Minimal output is for production throughput, never for the run you compare.
  4. Compare archive members by content hash, never cmp the tarball. tar and zip embed mtimes; cmp "proves" regressions that do not exist. Use scripts/pr85_hash_gate.py and scripts/pr87_root_tree_diff.py (NaN-aware).
  5. Run the config tripwire before anything expensive. scripts/cfg/prod_cfg_gate.py (rc 0 = the tree you point it at still compiles to the pinned operating point; on drift it names the key).

1. The chain at a glance

Minimal mode and source suppression are not the same thing. PR_MINIMAL_OUTPUT=1 lets the job write the Bee zip and pctree, runs the per-event nusel_extract.py that needs them, then deletes them: residual disk equals suppression, the per-event peak is one event's worth, and nusel-evt<ID>.tsv keeps its pctree-derived flags. 3. Multi-step and multi-event running

3.1 Stage A: group mode (run_chain_group.sh, doc 81)

One wire-cell process per step per group of 16 events. Production ran ./run_chain_group.sh <reco1.root> work-<s>-grp0825 data --size 16 --layout perevt, with two extra flags where needed: --fsproduct 'sbnd::timing::FrameShiftInfo_frameshift__FILTERFRAMESHIFT.' for the NCpi0 file (the FrameShift product sits under a different process instance there; the dump aborts rather than guessing, so grep the branch names of every new file), and --gbase 63 for the second of the two 2000-event files so its g0 does not land on the first's. Concurrency: SBND_MAX_JOBS groups at once (default 4; each imaging process is itself TBB-threaded).

Three default-OFF TLAs make it work, so a per-event run compiles byte-identically: multi_event=true (take each event's number from its tensor-set ident), rse_map={"<evt>":[run,subrun]} (a group can span runs; nueCC48 spans 12), evt_subdir='ql_evt%1%' (the runner creates the directories). With --layout perevt the group products are also split into the per-event layout, file-for-file identical to a one-event-per-process run (scripts/multi/split_group_products.py).

<out>/g<K>/{frames-dnn.tar.bz2, opflash_apa{0,1}.tar.gz, icluster-*.npz, pctree-ql.tar.gz, mabc.zip,
           events.txt, rse.json, wct_{dump,img,ql}.log, .{img,ql}.time.meta}

3.2 Stage B: per-event or group (run_pr_chain_batch.sh)

./run_pr_chain_batch.sh <ql_root> <out_root> data [evt ...], PR_JOBS events at once (default 6; production 32). With PR_GROUP_SIZE=16 it runs one process per 16 events instead; the PR job's TLAs are identical to the per-event ones except input, output_dir, multi_event, rse_map, so the 300+ knobs cannot drift between modes. Per-event logs are cut out of the group log; outputs land in the same pr_evt<ID>/ layout. It refuses a non-empty output directory it did not create.

5. Validation checklist

Tiered. T0 and T1 apply to any integration. T2 applies only when your job runs the same binary and config on the same stage-A inputs (then the answer is byte-identity, and anything else is a finding). T3 is the population comparison when the inputs differ (recob::Wire read live in LArSoft instead of dumped frames), and it is what you compare the four reference tables against. T4 checks that the shipped fixes still fire. Run from wcp-porting-img/sbnd/sbnd_xin/.

Interpretation traps (each has been fallen into at least once)

  • cosmict_flag is the cosmic verdict; cosmic_flag is not. cosmic_flag is a BDT input equal to !cosmict_flag_9 and reads 1 on 442/445 and 868/872 numu events.
  • nue_score == -15 means "not filled" (UbooneNueBDTScorer.cxx, br_filled != 1), not a score. It is the majority of both numu samples.
  • The degenerate class: nu_evaluated==1 but kine_reco_Enu == 0.0 exactly and vertex (0,0,0) exactly, always numu_score = -1.9416895. A ~1.5 cm unmerge shard the tagger selected; KineInfo never filled. 49 events (16 + 33), cut before every distribution here or they manufacture a first-bin spike (doc 85 §1.1).
  • kine_pio_flag == 1 is not "a pi0 was found": it is filled for the highest-energy shower pair whatever it is. The real gate is mass plus both gamma energies; "points at the vertex" is kine_pio_vtx_dis, not dis_1/dis_2.
  • The T_tagger row is not joinable to nusel-evt.tsv's main_id: unmerge_bundle / unmerge_assoc mint PR-internal cluster idents before the tagger runs. cosmict_score is never written (always 0).
  • Scores are unclamped since 2026-08-30 (range ±16.26). Anything quoting a ±4.30 ceiling or "nue>7 selects 0 by construction" describes the pre-clamp-removal chain (prod0825) and is history.

Pitfalls, ordered by how silently they go wrong

  1. Entry-point bypass. Calling clus_maker.pr() from your own jsonnet inherits C++ defaults, which are default-OFF so that config selects them. Absent means pre-flip behaviour, not production. Import the operating point; diff the compiled config to zero (T0).
  2. Vacuous gates. A gate that compares nothing passes (§2.3). Read the counts the gate prints, not its exit line.
  3. Single-filename ROOT writers. SbndPrMagnifyTrackingVisitor opens tracking-pr.root RECREATE and UbooneTaggerOutputVisitor UPDATE, every event, one fixed name. A multi-event lar -n 5 leaves an 8 KB file with T_tagger and T_kine absent and rc=0 (doc 5 G9). Per-event filenames or per-event processes until the writers are made append-safe.
  4. RSE. Everything inside the graph claims run 0 / subrun 0 unless the RSE is attached (wclsTensorSetMetadataAttacher + rse_from_metadata, doc 5 G3). Only Trun carries RSE; T_tagger/T_kine do not.
  5. The DL vertex fails silently into the geometric fallback. Count the WARN (T1). The reference has zero.
  6. Bee zip was load-bearing. The in-scope set was only recorded implicitly in mabc-pr.zip; turning it off silently killed nusel-evt.tsv until save_in_scope (doc 87 §4). Before dropping an output, find its implicit consumers.
  7. Idents not reset per event in a multi-event process change physics, not just labels (doc 81 §2).
  8. In-process gojsonnet in a long job: SIGSEGV at ~120 s (doc pr/97). Precompile where you can.
  9. --fsproduct per file. The FrameShiftInfo product name changes with the producing process; the dump aborts rather than guessing. MC reco1 files also need wire_product/badmask_product/summary_product overrides (simtpc2d).
  10. The knob comment can be false. use_power_recomb=false no longer restores "the byte-identical pre-pr/10 config" after the master merge (doc 87 §8); trust the compiled diff, not the comment.
  11. Two peers, one install prefix. A concurrent rebuild swaps local/lib under a running campaign; pin the binary (copy the libs, point LD_LIBRARY_PATH at the copy) before a long arm.
  12. Never write into an existing label. work-*, ref/prod-*, abtest/snap/*, decisions and label stores are records; a new run is a new label (M13).
